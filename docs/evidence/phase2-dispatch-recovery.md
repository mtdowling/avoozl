## Not done, and risks

- **Live caller identity is not proven.** Kiro Crew injects `kirocrew.caller`
  only into backends that advertise `kirocrew.caller-identity` and are pooled.
  Avoozl does not advertise it: its stdio server picks the workspace from the
  working directory, so one pooled process serving many folders could mix
  workspaces. In an unpooled session `plans_report` therefore refuses. A live
  worker needs either a per-session caller block for app servers from Kiro
  Crew, or Avoozl pooling-safe (one workspace per call). This needs a decision.
- A shell-capable agent can still start `avoozl mcp` itself and forge the
  block, as it can write SQLite through the CLI. The rule stops misattribution
  through the tool, not an agent with the user's shell.
- Priority is the existing `rank` field; no new `priority` field or
  label-based priority (§4.4) was added.
- A delivery in `decision` has no resolve operation yet; that is 2.12.
- No live run with a real worker session; proof P5 covers that.
- The temporary workspace from the packaged stdio check was left in the OS
  temp directory.
