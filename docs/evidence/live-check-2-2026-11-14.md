# Live check 2 in a second Kiro Crew gateway (2026-11-14)

Avoozl from `origin/main`, built with `npm run build:kirocrew-app` and
installed in a second Kiro Crew gateway (release build 0.12.2.4, Linux) with
its own `KIROCREW_HOME` and `KIRO_HOME`, so the main crew was never touched.

- Workspace: a new temporary one with two approved specs (`live2`, four
  leaves; `live3`, one leaf), one throwaway local Git checkout. No GitHub
  repository was read or written.
- No dashboard sign-in was used by any route. Checks that need the page, or
  a worker's report, are listed as skipped with the one click they need.
- Another worker's probe used this home for about 25 minutes (a hand-edited
  folder file, a replaced `tick.py`, a probe worker agent). Results from
  that window are not counted. The app was reinstalled from main afterward.

## One click to unblock the skipped checks

In the test dashboard: Customize, Connections, MCP Servers, `avoozl:avoozl`,
Approve. The share list entry is already set with `kirocrew config set`
(`mcp_gateway.stub_servers`); Kiro Crew keeps the launch approval to the
page.

## Findings

1. Kiro Crew gives no command for a chat folder's project directory, so a
   second home needs one click or a hand edit of its folders file.
2. A reinstall gives the tick cron a new job id. Kiro Crew then refuses its
   messages to chats the old job opened. Chats opened before a reinstall
   cannot be messaged by the new tick.
3. Avoozl marks a message sent when it plans it, so a refused one is not
   retried (`shortcut:` comment in `tick.py`).
