## Steps (design §8.2)

| #   | Step                         | Behavior                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| --- | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Token                        | Reads `X-OAuth-Scopes` from `GET /user`. Missing `repo`, `read:org` (or `write:org`/`admin:org`), `project` → fix `gh auth refresh -s <scopes>`. Fine-grained token: noted, each step finds out by reading                                                                                                                                                                                                                                          |
| 2   | Mode and planning repository | Reuses a named repository; in plans-repo mode creates a missing planning repository private, issues on, `auto_init`                                                                                                                                                                                                                                                                                                                                 |
| 3   | Issues                       | `PATCH has_issues: true` on the planning repository, or on each code repository in single-repo mode                                                                                                                                                                                                                                                                                                                                                 |
| 4   | Project                      | Picks by number, else finds by title, else `createProjectV2` then `updateProjectV2 public: false`. An existing public Project is reused as is and shown as public                                                                                                                                                                                                                                                                                   |
| 5   | Fields                       | Status: Todo, In progress, Done, Deferred, matched without case (a blank Project's `In Progress` maps `inProgress`). `updateProjectV2Field` resends every old option with its `id`, name, color and description, then re-reads and fails the step if one changed. Release: one option per milestone, missing ones appended the same way. Wave: `NUMBER`. Iteration only when asked. A same-named field of the wrong type is reported and left alone |
| 5b  | Views                        | `Board by release` (and `Table by wave` when asked): REST `POST …/projectsV2/{n}/views` with `vertical_group_by` and `group_by` first; on any failure GraphQL `createProjectV2View` and checklist item "In Board by release, Group by Release, then Save". No Roadmap view                                                                                                                                                                          |
| 5c  | Workflows                    | Reads `workflows { name enabled }` and compares with Requirement 33.6; every mismatch, every unlisted workflow, and every column or filter it cannot read goes on the checklist. No workflow call writes                                                                                                                                                                                                                                            |
| 6   | Epic issue type              | Organizations only; reused by name; created when the token has `admin:org` (else skipped with `gh auth refresh -s admin:org`)                                                                                                                                                                                                                                                                                                                       |
| 7   | Managed labels               | The six `managedLabels` keys in each repository issues live in (planning repository, or each code repository); names from policy, else `avoozl:<key>` as a proposal                                                                                                                                                                                                                                                                                 |
| 8   | `.avoozl.json`               | One diff: mode, planning repository, Project owner and number, field names that exist, mapped `statusValues`, `epicIssueType`, each repository's `managedLabels` and `baseBranch` (the default branch). Validated with `normalizeGitHubPolicy`; saved only by the person                                                                                                                                                                            |

## Proved by fake-GitHub tests

| Test                                                   | What it shows                                                                                                                                                                                            |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| preview lists every write and writes nothing           | 0 logged writes; each write names step, object, owner, name, visibility; no Roadmap                                                                                                                      |
| confirm runs the preview; a second run changes nothing | First run creates repository, Project (private), Deferred option with old ids kept, Release `one, two`, Wave, Board view, Epic, 6 labels; proposal valid. Rerun: `nothingToChange`, no write, diff empty |
| existing Status options keep ids, colors and names     | Old options byte-equal after the run; Release gains `two`; Iteration and Table by wave made; issues turned on                                                                                            |
| wrong-kind field                                       | Text `Release` reported, not touched, left out of the diff; public Project stays public                                                                                                                  |
| REST views with grouping                               | Board grouped by Status columns and Release; no grouping click on the checklist                                                                                                                          |
| permission failure in one step                         | Labels 403: step failed with fix, the other steps done; Project create refused: fields and views skipped, labels and Epic done                                                                           |
| no project scope                                       | No GraphQL call; token, project, fields, views, workflows show `gh auth refresh -s project`; repository and labels still done                                                                            |
| workflow checklist                                     | Auto-archive on → "turn Off"; Auto-add off → "turn On"; unlisted ones → "cannot read"; Auto-close on → no item                                                                                           |
| stale preview hash                                     | 409, no write                                                                                                                                                                                            |
| single-repo mode                                       | Issues on and labels in each code repository; no Release without a named release, then made from `releases`                                                                                              |
| through Operations                                     | Release from a spec manifest milestone; proposal saves through `github.settings.update`; rerun is "Nothing to change"; `plans_github_setup` listed                                                       |

No delete, rename, recolor or visibility change of an existing object: every
test that writes checks the log has no `DELETE`, the only `PATCH` is
`has_issues: true`, and `updateProjectV2` carries only `public` on a Project
the wizard just made.
